# Farm Gameplay 01 — Sim Port & Parity

**Phase:** 1 · **Blocks:** framework/02 (state types), tui/01, gameplay/02
(coins accessor) · **Parallel-safe with:** framework/01

## Goal

Port v1's simulation engine and content **verbatim** and prove it: same
inputs ⇒ bit-identical states across v1 and v2. Every other task builds on
this being boring.

## Sources

| Source | Role |
| --- | --- |
| `../../ssh-idlefarmer/internal/sim/*.go` | the code being ported (state, advance, actions, derive) |
| `../../ssh-idlefarmer/internal/content/*.go` + `data/*.toml` | content loader + crop/balance data — copied unchanged |
| `../../ssh-moonminer/docs/README.md` | sim-purity convention (no I/O, no clocks, injected time/RNG) — v1 already complies; keep it that way |

## Deliverables

- `internal/sim/`, `internal/content/`, `data/` (including `embed.go`)
- Two tiny additive accessors (below) — the only allowed changes

## Spec

- Port = copy + rename module paths + `go vet` clean. Resist refactors;
  diff-against-v1 should be reviewable in minutes.
- **State encoding stays byte-compatible with v1** (same JSON field names,
  same `Version`). `sim.DecodeState` must accept every blob a v1 database
  can contain — that is the entire basis of `import-v1` (framework/02).
  If v1 has multiple historical state versions, port every decode path.
- **Allowed additions** (leaderboard needs, sim purity intact):
  - `(*State) Coins() int64` — the current coin balance the leaderboard
    ranks on (exact field name per v1's state; expose whatever "coins"
    means in v1 — the spendable balance, not lifetime earnings. Note in a
    comment that rebirth resets it and that's accepted/intended:
    the board rewards current wealth, and post-rebirth players climb back
    fast. A "lifetime earned" board is a possible v2.1 second tab —
    TODO, don't build).
  - `(*State) FarmName() string` / `SetFarmName(string)` — if v1 stores
    the name in state (it does — the `ovName` overlay edits it), keep it
    there; moderation wraps `SetFarmName` at the action layer
    (gameplay/03), never inside sim.
- Offline catch-up (`sim.Advance`, `Events`) ports unchanged — v2 keeps
  the welcome-back summary.

## Parity harness (the point of this task)

- **Golden states**: check in a set of v1-produced state blobs
  (`testdata/v1/*.json`) generated by a small throwaway program run
  against the actual v1 module — document the generation command in the
  testdata README so goldens are reproducible.
- Tests: each golden decodes; re-encoding is byte-identical; a scripted
  action/advance sequence applied in v2 matches a committed v1-produced
  result state (generate with the same throwaway program).
- Edge goldens: fresh save, mid-rebirth save, max-land save, save with
  offline catch-up pending, save with a farm name set.

## Acceptance criteria

- [ ] `go test ./internal/sim ./internal/content` green, including v1's
  ported test suite and the parity goldens.
- [ ] `diff -r` between v1 and v2 sim trees shows only module paths,
  the two accessors, and nothing else (attach the diff to the PR).
- [ ] `data/*.toml` byte-identical to v1's.

## Out of scope

- Moderation of `SetFarmName` input → gameplay/03 (action layer).
- Any balance change, however tempting → TODO file only.
